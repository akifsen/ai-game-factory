# V0.8-3C candidate evidence (C2-B)

C2-B wires the production `CandidateEvidenceExporter` staging callback, trusted
`python -I` cold verification, and insert-only publication of manifest/result/marker
artifacts under a held `BEGIN IMMEDIATE` writer lock. Publication uses a same-volume
directory rename that refuses to overwrite an existing destination (`os.rename` on
Windows and `renameat2(RENAME_NOREPLACE)` on Linux),
stores a versioned publication-result envelope plus marker-bound cold payload digest (D1),
and readiness revalidates semantic cold provenance (not hash rebound alone).

- `candidate_workflow_readiness()` remains the C1 pre-evidence currentness query.
- `candidate_evidence_readiness()` / `assert_candidate_evidence_complete()` attest
  committed evidence artifacts and re-check upstream bindings.

Integration tests call `bind_production_candidate_evidence_exporter()` explicitly;
there is no public CLI surface for promotion or production eligibility.

`prepare_evidence_publication_container()` enforces the same known layout as readiness
(`assert_known_published_evidence_container_layout`) after writing marker/result siblings
and before computing the Dready fingerprint, so extra staging-root siblings fail before
publication rather than only at readiness.

Publication matrix unit tests prove COMMIT denial on SQLite authorizer param1 (`COMMIT`)
after exactly three uncommitted C2 artifact inserts, INSERT denial after the first
uncommitted C2 row on the held writer connection, syscall races injected immediately
before `os.rename` / Linux `renameat2`, concurrent CAS from managed
`.gf/candidate_evidence_staging/stage_*` copies, and currentness mutations during cold
(not under held `BEGIN IMMEDIATE`). The integration test runs real Blender and Godot with explicit
`assert_zero_provider_activity` (invocations, intents, cost ledger), a single rig-oracle
execution attempt, stable source bytes, and `assert_candidate_evidence_complete` plus
engine-finalized readiness.
