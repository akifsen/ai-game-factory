# V0.8-13 compare-session integration

An optional session panel lets each side of the animation comparison record
Keep/Revise, a note and the current clip-local bookmark in an existing review
session. Both cards share one session revision and raw-SHA authority through the
existing one-shot review-session bridge. The panel does not write session files
or open the workflow database directly.

## Launch

Pass a matching `BridgeContext` and optional trusted `python_executable` as
keyword arguments to `prepare_animation_review_compare_viewer` or
`run_animation_review_compare_viewer`. The workflow, project, preview, review set
and ordered clip packages must match the comparison arguments. The context's
exchange directory must meet the existing bridge path rules; preparation stages
a separate exchange directory and `context.json` in the owned overlay.

Without `session_context`, existing comparison calls and scene behavior remain
unchanged. With a context, the launcher selects the session wrapper scene and
passes the existing session bridge arguments. The wrapper instances the existing
comparison once and reserves space for two annotation cards. A missing saved
session is shown read-only; create it through the existing session workflow.

## Saving annotations

Each card shows its selected clip's saved status, note and bookmarks. Keep/Revise,
Save Note and Bookmark Current submit one operation at a time with the latest
acknowledged SHA. A bookmark records normalized progress multiplied by that
pane's measured clip duration, in seconds: progress 0.75 and duration 1.5 seconds
produce a 1.125-second bookmark.

Selection changes resolve the new clip before submitting an operation. Pending
operations retain their captured target. Saving or reloading preserves the
other clip's unsaved note and any newer text typed after submission. Undoing a
draft to the saved note lets a fresh reload display a subsequent authority update.

Conflicts require reload and disable further edits without claiming a save.
Failed status changes restore the saved status. Historical annotations remain
readable when authority is stale or unavailable; recovery requires fresh reload.
Session responses do not alter comparison progress, playback speed or poses.

## Stored bookmark navigation (V0.8-14)

Each pane exposes Prev, a stored-order bookmark list, Next and Go. Navigation is
read-only: it never calls the session bridge or changes revision or raw SHA.
Bookmarks load from the cached session for the pane's currently selected clip,
including when authority is stale, conflicted or offline. Invalid stored times are
omitted from the list; out-of-range navigation requests fail closed.
If live compare clip ids differ from the pane targets used to populate bookmark
lists, navigation fails closed with `clip_target_changed` until the controller
syncs on the next frame.

Seeking uses clip-local seconds divided by that clip's bound duration to set
shared normalized progress, pauses playback, and samples both panes. With two or
more stored bookmarks, Prev at the first and Next at the last are no-ops. With
exactly one stored bookmark, Prev and Next both seek to that bookmark when
playback is off it; when already at that bookmark they are idempotent no-ops.
Go and list selection always pause and seek to the chosen stored bookmark, even
when that bookmark is already selected and playback is already at its normalized
time. Empty bookmark lists make Prev/Next no-ops. Reload and committed updates
refresh lists without discarding note drafts.
