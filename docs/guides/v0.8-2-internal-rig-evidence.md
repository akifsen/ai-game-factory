# V0.8-2 internal rig evidence guide

## Export

```python
from pathlib import Path
from gamefactory.adapters.assets.internal_rig_evidence import export_rig_evidence_bundle

export_rig_evidence_bundle(
    Path("humanoid.glb"),
    Path("rig-bundle"),
    godot_executable=Path("/path/to/godot"),
)
```

Without `godot_executable`, the bundle contains static validation and reviewed tool copies only (no runtime roles).

## Cold verification

Use the **trusted** verifier from the installed package or repository checkout — never execute a `verify_rig_bundle.py` copied inside the bundle:

```bash
python -I /path/to/trusted/verify_rig_bundle.py /path/to/rig-bundle
```

The first stdout line is `CONSISTENT_BUT_UNAUTHENTICATED` (integrity checks passed for an unsigned bundle) or `FAILED`. The second line is a JSON summary with separate `integrity_outcome` and `execution_provenance` fields.

## Pinned reviewed artifacts

Export with `godot_executable` runs the trusted cold verifier on the staged bundle before publish.

The cold verifier pins:

- `humanoid_12bone_contract.json` (canonical JSON digest; raw bytes identity is checked via manifest/report/bindings)
- `export_humanoid_12bone_fixture.py` (LF-normalized text)
- `skin_deformation_harness.gd` (LF-normalized text + raw bytes)
- `validator_contract_version` string (`humanoid_12bone_v1`)

Rebuild `verify_rig_bundle.py` after changing embedded GLB logic:

```bash
python scripts/build_verify_rig_bundle.py
```

## Runtime region semantics

Oracle requests carry `region_boundary_tolerance` (must be exactly `1e-6`). Population counts and vertex sampling use this value only for axis-aligned region **inclusion** (vertices within `1e-6` outside a box face still count as inside). Integer count fields in the request digest are canonicalized as strict integers on both Python and Godot sides so cross-language digests match after JSON parse. Python digest hashing also normalizes the tolerance literal to `0.000001` to match Godot `JSON.stringify`.
