# V0.8-12 animation comparison

Disposable Godot overlay for synchronized side-by-side comparison of two clips from one **current** V0.8-8 animation review set.

## Python API (supported entry points)

This slice exposes **prepare/run helpers only**. There is no supported `python -m` or console-script CLI for compare launch.

```python
from gamefactory.cli.animation_review_compare_viewer import (
    prepare_animation_review_compare_viewer,
    run_animation_review_compare_viewer,
)

prepared = prepare_animation_review_compare_viewer(
    handlers,
    workflow_id,
    preview_dir,
    clip_packages,
    review_dir,
    overlay_dir,
    left_clip_id,
    right_clip_id,
)
argv = prepared.godot_argv(godot_executable=godot_path)
```

`prepare_animation_review_compare_viewer` gates `animation_review_set_current` before capture and again after overlay materialization plus compare resource install, re-checking canonical review-set bytes against the initial snapshot. Clip selectors are validated against the captured manifest (not a pre-capture read). `run_animation_review_compare_viewer` re-gates currentness immediately before launching Godot, owns a temporary overlay directory, and cleans it up after Godot exits.

## Godot scene

`animation_review_compare.tscn` renders two independent `SubViewport` panes with the trusted review-set preview player, shared normalized timeline transport, and per-pane canonical rest-bounds camera fit. Each pane fits using that `SubViewport`'s visible rectangle and canonical edge margins (split layout excludes the bottom control panel from the 3D viewports).

## Playback controls

The overlay starts paused at normalized progress zero. Play advances one shared
clock, Pause freezes both poses, Restart returns both panes to zero and the seek
slider samples the same normalized progress in both clips. Each pane samples
`progress * its_clip_duration`; the shared clock uses the longer clip duration.
Both clips hold their final pose at progress one. Shared speeds are 0.25, 0.5, 1
and 2; changing speed preserves the current progress.

Each pane has a clip selector. The two selected clips must be distinct members
of the captured review set. An accepted change pauses both panes, resets all
bone poses and returns progress to zero while preserving the shared speed.
Rejected selections restore the displayed selection and leave the comparison
state unchanged. Resetting all poses prevents tracks absent from the new clip
from retaining the old clip's transforms.

The panes have independent effective 3D worlds, actor instances, animation
clones, cameras and lights. Their animations use manual sampling, so inherited
preview autoplay and loop settings do not advance either pane independently.

## Camera fit

The bottom transport panel lives outside the `SubViewport` split (`ViewportSplit` is offset above the panel). Safe projection rectangles are derived per pane from `SubViewport.get_visible_rect()` with fixed edge margins; no cross-coordinate mapping from the main window control panel.

The overlay reads a disposable captured review-set snapshot. It does not save
comparison selections, playback state, annotations or source changes. Currentness
is required during preparation and checked again immediately before launching
through the run helper; an already launched snapshot is historical if its live
source later changes.

The [technical closure](../reports/v0.8-12-animation-compare-technical-closure.md)
records source and independently installed-package qualification, including
actual authored-package rendering, weighted deformation and source-drift gates.
Public release qualification remains separate.
