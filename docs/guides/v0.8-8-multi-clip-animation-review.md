# V0.8-8 multi-clip animation review

The review set combines two to eight current V0.8-6 authored animation packages
for one verified character into one Godot scene. The caller's order determines
the selector order. Every clip ID must be unique, and every source must share
the same workflow, evidence lineage, rig, verified GLB, and weighted bone
capability. The package remains test-only; production and promotion eligibility
are false, and the public rigged-character profile remains unsupported.

## Export and currentness

```python
from gamefactory.workflows.v08_candidate_animation_review_set import (
    CandidateAnimationReviewSetSource,
    animation_review_set_current,
    export_rigged_character_animation_review_set,
)

sources = (
    CandidateAnimationReviewSetSource("wave-preview", "clips/wave.json"),
    CandidateAnimationReviewSetSource("idle-preview", "clips/idle.json"),
)
review = export_rigged_character_animation_review_set(
    handlers, workflow_id, "character-preview", sources, "review-set-out"
)
assert review.ordered_clip_ids == ("wave", "idle")  # IDs in the authored JSON
assert animation_review_set_current(
    handlers, workflow_id, "character-preview", sources, review.review_set_root
)
```

Create the character preview and both authored clip preview packages through
their existing public exporters first. The set exporter calls the public
V0.8-6 currentness authority three times per source: before staging, before
publication, and after publication. The currentness API calls it once per
source. Each gate is surrounded by exact snapshots of all ten source files;
the whole collection is pinned again to catch an earlier source changing
while a later source is validated. Sources and authored JSON are not modified.

Repeated exports from the same ordered inputs produce identical package bytes.
The destination must be fresh. A stale source prevents publication; a detected
change immediately after atomic publication leaves an immutable stale output
and raises an error. Choose another destination after resolving the source
change.

Stale or malformed sources make `animation_review_set_current` return `False`.
Malformed review layouts and manifests raise `ValidationError`; inconsistent
review digests raise `CandidateCurrentnessError`. Coherently rehashed review
content that disagrees with the captured live sources is stale.

## Package layout

There are thirteen root files and two original files in each numbered clip
slot, `clips/000` through at most `clips/007`. Each slot preserves the source
`animation_clip.json` and `animation_clip_manifest.json` bytes. The set manifest
binds ordered clip IDs, raw clip and original manifest hashes, all ten original
source file digests, and shared evidence identity. The root contains one GLB,
character, player, and review UI rather than separate characters per clip.

The generated `project.godot` opens `animation_review_set.tscn`. Root and nested
manifests are bounded to 64 KiB, and the output file bytes are bounded to
128 MiB. Layout inspection rejects extra files, linked paths, and oversized
inventories. Identical shared source bytes are reused in memory within a
capture batch.

## Godot controls

Open a consumer copy of the exported directory in Godot. Importing creates
Godot cache files; the canonical package must retain its exact layout for
currentness checks.

The clip selector pauses playback, resets bone poses, selects the new clip,
and seeks to zero. Session speed and loop override persist across selections;
authored animations remain unchanged. Play, Pause, Restart, scrub, and
0.25/0.5/1/2 speed controls work for the selected clip. Unknown selections leave
the current state unchanged. Switching uses one skeleton and player, with
no blending, retargeting, root motion, or animation editing.

The real integration acceptance generates two V0.8-6 packages from the same
Blender/Godot evidence, exports the set, launches a consumer copy, and exercises
the packaged inspector. It checks disjoint clip deformation, controls, camera
behavior, coherent nested tamper rejection, and original source/output byte
preservation. This acceptance is separate from release-wheel and CI evidence.
