# AI Game Factory v0.5.1

Package version `0.5.1`. A recovery-fix release on top of V0.5 (`0.5.0`). It contains three isolated fixes found while running the V0.5 production candidate. Asset profiles, specification schemas (`asset-spec-0.5.0`, `asset-profile-0.5.0`) and evidence schemas (`asset-evidence-0.5.0`, `production-receipt-0.5.0`) are unchanged.

## Highlights

### Safer Godot recovery

Commit `e7cb2c6e452ebdd104d5803232c98f72e20180fc` — `fix(engine): make pre-launch Godot unavailability retryable`

- A missing, nonexistent, non-file or non-executable Godot path is detected before any process launch and raised as `ToolUnavailableError` (code `TOOL_UNAVAILABLE`, a `ToolExecutionError`), which is retryable.
- Failures after Godot launches (engine import, runtime validation) still raise `EngineImportFailedError` / `RuntimeValidationFailedError` and stay non-retryable.
- A local tool-path configuration problem no longer forces a rebuild of an already-produced asset.
- `ProcessRunner` is unchanged. There are no task-id special cases.

### Correct paid-cost settlement

Commit `61a622029e6a7e9e2a9fcdc90217b6fddeab28fa` — `fix(accounting): settle successful paid execution to actual cost`

- When the provider reports terminal `SUCCESS` with a known actual cost, the paid execution settles to that actual cost (for example 20 reserved / 15 actual settles to 15; an actual above the reservation settles to the actual).
- In-flight, uncertain and raised provider calls keep the conservative `max(reservation, known actual)`. `SUCCESS` without a reported actual keeps the reservation.
- The change is prospective. Historical accounting rows are not rewritten.

### Correct 3D camera framing

Commit `1c7a9136e061999edb909d8a572c3318b14933bd` — `fix(render): account for view-axis depth in camera framing`

- Perspective framing projects the AABB onto the camera basis and accounts for the depth of the box along the view axis (near-face distance), in both the Python framing contract and the Godot runtime harness.
- Fixes the top-view overcorrection on tall, thin assets such as pickups.
- Applies generically to `static_prop@1`, `pickup@1` and `modular_piece@1`. There are no asset-, profile- or view-specific constants.

## Known follow-up items — not fixed in 0.5.1

1. **Secret redactor, short values.** A secret-like environment variable with a very short or common value (for example `1`) can corrupt unrelated output, fingerprints or task IDs.
2. **Accounting reconciliation.** Historical paid-execution reservations, and those left after crash/recovery before this settlement fix, may remain overstated. No reconciliation tool exists yet.
3. **In-revision concept supersession.** A rejected concept still requires a new asset revision. There is no in-revision supersession workflow.
