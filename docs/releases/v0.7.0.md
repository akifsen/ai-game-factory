# AI Game Factory v0.7.0

Package version `0.7.0`: advanced asset profiles (ADR 0013–0018).

## Highlights

- **New profiles.** `vehicle@1`, `weapon@1` and `aircraft@1` are assemblies of named, movable parts authored by an operator. `character@1` is a provider-generated single mesh with a capsule collider. `rigged_character` stays UNSUPPORTED.
- **Assembly workflow.** `gamefactory asset register-source` writes the source registration (hash, `paid: false`, required `source_front`); `gamefactory asset assemble` runs prepare → normalize → validate → Godot → final review → evidence, with no concept, provider or paid step.
- **Declared orientation only.** A `+Z` source (Blender's default glTF export) gets exactly one 180° turn about +Y at the root; a `-Z` source is kept byte-for-byte; nothing is inferred.
- **Composed validator.** Closed rule groups selected by capabilities; new rule ids for parts, pivots (including `pivot.collapsed`), sockets, orientation and capsules. The three historical profiles report exactly what V0.6 reported.
- **Godot articulation.** The runtime harness checks the imported part tree, pivots and sockets and moves every movable part about its declared pivot, asserting that nothing else moves.
- **All review views placed.** `rear`, `left`, `right` and `three_quarter_rear` gain cameras; unknown views are errors, not a three-quarter fallback.
- **Evidence 0.7.** `asset-evidence-0.7.0` and `production-receipt-0.7.0`; the stdlib cold verifier recomputes the normalization from the retained source and rejects paid or mixed role sets.
- **Linux CI fix.** Golden GLB comparisons no longer depend on the platform's PNG encoder.

## Compatibility

Historical schemas, profiles, fingerprints, paid requests and evidence bundles are unchanged. `gamefactory asset profiles` now lists the V0.7 profiles after the historical ones, and `character`, `weapon` and `vehicle` are no longer UNSUPPORTED.

## Upgrade notes

- Write the source front with `=`: `--source-front=+Z` or `--source-front=-Z`.
- Assemblies are processed without Blender; an assembly that needs LOD1 must provide `SM_<asset>_<part>_LOD1`.
