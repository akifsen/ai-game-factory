# V0.8-9b review session UI foundation checkpoint

The separate Godot session scene composes the existing V0.8-8 playback scene and adds clip status, UTF-8 bounded notes, bookmark creation/seek, reload, and session creation controls. It uses asynchronous one-shot Python requests with explicit argv and keeps playback responsive. The launcher and complete persistence acceptance remain pending.

Response presentation requires exactly the six bridge fields, typed boolean flags, success `error: null`, and a closed failure object. Successful create/update requires a committed stored session with a valid raw SHA and closed domain presentation. Failed or ambiguous transport requires reload before editing; historical results remain read-only. Pending note saves use the submitted clip's draft and preserve later edits and other clips' drafts.

The panel reserves the lower 260 pixels for playback controls, uses a scrolling container, and adjusts width on resize. Child processes run without a console window. Exchange names include process ID, randomness, and a counter. The bounded bridge timeout is 600 seconds; timeout never implies that no durable write occurred.

Independent source review approved this foundation after response, draft, and reload corrections. On Godot 4.7.2, the Team Lead independently ran import, script check-only, and the minimal-scene protocol probe: all exited zero without script errors in 3.13 seconds. The same applied-source checks passed. The probe uses a minimal playback stub and does not prove actual playback or Python bridge integration.

This checkpoint does not complete V0.8-9, qualify a release, or demonstrate actual session reopen/conflict/currentness UI acceptance. Those require the disposable overlay launcher and a real Godot-to-Python subprocess lifecycle.
