# V0.8-13a compare-session runtime checkpoint

The optional A/B session wrapper reuses the existing V0.8-9 bridge, workflow and
store without changing their schema or authority rules. One session revision and
SHA serve both cards. Existing sessionless comparison behavior is preserved.

The bounded runtime slice passed independent Team Lead verification: 28 focused
tests, zero failures or skips, including the original 15 comparison tests and
13 added API/path/Godot probe checks. The isolated-source run passed in 8.40
seconds; the applied checkout passed the same suite. Ruff and whitespace checks
passed. A separate reviewer found no remaining concrete blocker in the corrected
runtime paths.

Real Godot controls and the existing in-memory compare player verify immediate
selection targets, bookmark time from measured duration, rejected duplicate
selection, shared SHA request construction, cross-pane and newer note drafts,
valid read/update response semantics, conflict after selection, rejected-status
restoration and preserved comparison transport. An edit/undo/reload regression
prevents a stale draft from masking a fresh saved note. Python tests cover
optional contexts, identity mismatches, unsafe sidecar paths, argv and cleanup.

Earlier failed test attempts are retained as failures: the scene check used
`--scene --check-only` and timed out; a subsequent panel probe had invalid
same-clip selection, duration and response expectations. These checks were
replaced with an explicitly terminating panel probe and valid protocol fixtures.
Unrelated generated scripts and lockfile changes were excluded from the patch.

This is **fast runtime qualification only**. The panel probes intercept bridge
requests and use in-memory clips; they do not establish real session writes,
actual authored-package rendering or installed-wheel acceptance. Those checks
must extend the existing real-tool lifecycle before V0.8-13 technical closure.
No CI jobs, shards, frozen candidate nodes or timeout limits were changed.
Production/promotion eligibility remains false; no provider feature was added.
