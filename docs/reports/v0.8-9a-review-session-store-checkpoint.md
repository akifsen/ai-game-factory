# V0.8-9a durable review session store checkpoint

This checkpoint adds local sidecar storage to the approved session domain. Live V0.8-8 workflow currentness, the command bridge, and the Godot session interface remain separate work.

The store accepts an explicit session path outside the canonical review tree, or derives a separate sibling directory from the normalized review-root identity. Historical loading uses strict bounded JSON and returns the exact raw file SHA-256, including any valid noncanonical whitespace. Updates compare that raw digest under a retained cross-process writer lock, apply one domain operation, flush and fsync an exclusive sibling temporary file, and atomically replace the session. Fresh creation uses a single rename after the final absence check under the same managed-writer lock. It exposes a complete single-link file to concurrent readers.

Create and update support a final precommit callback after staging. The later workflow layer must supply live review-set authority there. The store alone does not establish currentness or approve production. It rejects review-tree storage, unsafe link/reparse paths, hardlinked session files, oversized lock files, malformed or oversized JSON, stale expected digests, and invalid domain inputs. Failure cleanup touches only the writer's temporary file. These concurrency guarantees apply to writers using this store; arbitrary external filesystem mutations are outside the transaction.
