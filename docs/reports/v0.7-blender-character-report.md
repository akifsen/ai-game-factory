# V0.7 static character Blender processor

## Scope

This slice introduces `CharacterProcessor` for a typed, provider-generated,
single-mesh V0.7 character specification with no parts or sockets and a runtime
capsule collider. The adapter requires an expected raw-GLB SHA-256, performs a
bounded 50 MiB static-GLB inspection before Blender starts, rejects skins,
animations, joints, weights, extensions, malformed geometry and over-budget
inputs, and verifies that the source is unchanged after processing.

The standalone Blender script imports the hash-pinned source snapshot, bakes
static object transforms, joins visual meshes, fits height with one uniform
scale, and applies only the requested center or bottom-center translation. It
writes exact `SM_<asset_id>_LOD0` and `SM_<asset_id>_LOD1` visual nodes and no
collider mesh. The capsule remains runtime data. The LOD1 report distinguishes
decimation from an unchanged fallback; fallback is allowed only if its actual
triangle count fits the LOD1 budget.

The adapter independently runs the V0.7 geometry validator on exported bytes,
checks exact mesh names, geometry budgets, materials, textures, bounds, origin
and capsule fit, and compares the oriented LOD0 triangle soup against the
hash-pinned source after the reported uniform transform. Report claims are
checked against decoded output. Contracts and reports are limited to 1 MiB;
GLBs are limited to 50 MiB. Attempt-specific staging, exclusive contracts,
no-replace hard-link publication and unchanged-file cleanup protect existing
or foreign files. Results are immutable and JSON-serializable and bind source,
output, spec, profile, script and Blender version hashes/identities.

## Verification

The focused command passed **25 tests**, including real Blender 5.2.1 LTS runs.
Regression tests reuse authentic, outside-Blender-validated exports, change
only the fully bound report's `uniform_scale` to JSON `true` or an overflowing
integer, and confirm controlled rejection. Report parsing also rejects
duplicate keys and overflow/non-finite numbers; all numeric report
bindings/metrics enforce finite numeric or strict integer types (so booleans
cannot pass as numbers). Publication-failure tests inject identity-read errors
after each hard link and verify only this attempt's still-owned output is
removed; a foreign replacement remains intact.

```powershell
.venv\Scripts\python.exe -m pytest tests/unit/test_character_processor.py tests/integration/test_blender_character_processor.py -q --basetemp .verification/blender-character-final-tests
```

The integration fixture contains two translated static mesh nodes and declares
0.6 × 1.8 × 0.4 m bounds, bottom-center origin and a 0.3 m radius / 1.7 m high
capsule. Blender produced exact target bounds; LOD0 had 24 triangles and
decimated LOD1 had 12. Both fresh runs passed the outside-Blender V0.7 validator
and had matching geometry metrics and transforms. The source hash remained
unchanged. The test is a processing geometry fixture, not a claim of a polished
character asset.

Ruff check/format, mypy and `git diff --check` passed for the four implementation
and test files. Pytest reported an environment warning because the sandbox
denied access to `.pytest_cache`; all assertions passed.

No provider calls, database writes, workflow/CLI registration, profile
availability change, commit or push are included.

## Independent final review

Quality decision: APPROVED for the standalone Blender character slice, not character production availability.

Root independently ran 172 tests in 44.01 seconds: 25 processor/real-Blender tests, 42 V0.7 geometry tests and the unchanged 105 V0.6 behavioral goldens (`.verification/character-root-final-publication.log`). Ruff and mypy passed. An independent reviewer approved the final revision.

Review corrected strict numeric/report binding validation (booleans, nonfinite and oversized integers, duplicate JSON keys) and publication rollback after identity-read failure immediately following either hard link. Tests use valid real Blender output to avoid masking malformed-report acceptance with a different failure. Incomplete attempts remove only linked files still matching the validated staging inode, size and digest; changed foreign replacements survive. ADR 0015's max(width, depth) capsule sanity contract remains intact.

The fixture demonstrates static geometry processing and semantic reproducibility, not artistic humanoid quality. Runtime capsule verification, paid workflow/provider evidence integration, installed-wheel acceptance and built-in availability remain separate gates. No paid provider call was made.
