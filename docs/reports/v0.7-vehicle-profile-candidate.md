# V0.7 private vehicle profile candidate

Date: 2026-09-30

## Scope

Added `vehicle@1` profile data and the `armored_vehicle_test` V0.7 assembly
specification. The profile accepts only `local_operator_assembly`, uses the
shared assembly geometry mode, requires a fixed hull, a +Y-revolute turret, a
+X-revolute barrel, a −Z-facing forward-end muzzle, generated LOD1, a root box
collider, static-body review, and all nine explicit review views. The profile
was bound only through a test-local `ProfileRegistry`; the builtin registry
remains closed and continues to list `vehicle` as unsupported.

The integration fixture builds separate hull, turret, and barrel box meshes
with distinct dimensions and nonzero parent-relative pivots. Its measured
rest bounds match the specification at 2.8 × 1.175 × 3.82 m with no resizing.

The candidate sets a profile-specific framing target of 0.48 while leaving the
legacy `static_prop` target at 0.55. The lower target is a conservative fit for
this wide vehicle across its nine-view landscape review set; it is profile data,
not a change to the shared framing algorithm or a new global default. In the
real 1280 × 720 Godot run, measured vertical screen fractions were 0.358 for
front/rear, 0.262 for left/right/side, and approximately 0.480 for the three
quarter and top views. All nine remained inside the profile's 0.20–0.75 limits,
inside the viewport with the configured 0.04 margin, and needed no camera
correction. This documents the tested 16:9 case only; it does not claim
coverage for other aspect ratios.

## Verification

- `tests/unit/test_vehicle_profile.py`: **4 passed**. Checks typed profile/spec
  binding, private registry isolation, public unavailability, role motion axes,
  required muzzle role/placement, and profile-semantic negative specs.
- `tests/integration/test_vehicle_profile_runtime.py`: **1 passed** using
  Blender 5.2.1 and Godot 4.7.2. The real Blender processor generated LOD1; the
  decoded output passed source-to-processed preservation and V0.7 validation.
  Godot verified articulation and rest-pose restoration, the collider ray hit,
  and nine decoded 1280 × 720 captures. Independent GLB validation rejected
  wrong barrel axis, wrong barrel parent, wrong muzzle orientation, and a muzzle
  moved behind the barrel with their dedicated rule IDs.
- Combined candidate and existing profile/spec run: **112 passed**. The
  resource-inventory assertion now expects the three historical YAML resources
  plus the explicitly scoped `vehicle.yml` candidate, and independently asserts
  `builtin_registry().get_v07("vehicle", 1)` still rejects it as unsupported.
- Ruff: **passed** for the new Python tests.
- Mypy on test modules: **not clean** because this repository is imported as an
  installed package without a `py.typed` marker, so mypy reports imports as
  `import-untyped`; no production Python module was added or modified in this
  slice.

No workflow, approval, production database, provider, paid request, or cold
evidence export was run. This is a privately tested profile candidate, not a
claim that `vehicle@1` is available or product-ready.
