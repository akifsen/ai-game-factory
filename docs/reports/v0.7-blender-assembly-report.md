# V0.7 standalone Blender assembly processing

## Scope

This slice adds a separate `AssemblyProcessor` for authenticated, retained
`local_operator_assembly` packages. It leaves the legacy single-mesh Blender
processor and its packaged script unchanged. The adapter verifies the mandatory
provenance digest and typed assembly profile before invoking Blender, rejects
linked paths and existing targets, and bounds retained, processed, and oracle
GLB reads to 50 MiB. Blender writes to same-directory staging artifacts; the
completed GLB and report are published with no-replace hard links, so a target
created concurrently is preserved.

The packaged Blender script uses only its standalone Python and `bpy` runtime.
It preserves the identity `ROOT`, declared part and socket hierarchy, local
transforms, extras, and LOD0 mesh data. It applies the one allowed `Ry(180°)`
normalization to the logical root part only for a pinned `+Z` source. It does
not resize, recenter, reparent, or join authored meshes. When required, LOD1 is
generated as an identity child of each corresponding part, and an identity root
box collider is generated from the canonical rest bounds.

The adapter independently decodes the exported GLB after Blender exits. It
checks source-to-output oriented LOD0 triangle preservation, identity and
hierarchy constraints, LOD1 structure, box face coverage and bounds, dimensions,
origin, material and texture budgets. A Blender success report alone cannot
produce a successful result. The returned value freezes its nested report data;
its JSON form omits the retained source byte snapshot.

## Review follow-up

The follow-up hardens the contract and report boundaries to a 1 MiB limit.
Serialization enforces the contract limit before creating its file; both the
adapter and standalone Blender reader consume at most limit + 1 bytes and
reject non-object JSON. The adapter reads diagnostics contracts and result
reports through bounded regular-file checks. It removes its exclusive contract
file in `finally` only when device/inode, size, and SHA-256 still match the
captured contents. Blender's staging cleanup applies the same unchanged-file
rule to staging artifacts. Replacement and same-inode mutation tests verify
that foreign contents are preserved.

After these review fixes, the combined focused command
`.venv\Scripts\python.exe -m pytest tests/unit/test_assembly_processor.py tests/integration/test_blender_assembly.py -q --basetemp .verification/blender-native-final-tests`

## LOD1 bounds integration correction

A Team Lead real workflow fixture exposed naive decimation losing canonical
world-space part extrema under a 30-degree root rotation. LOD1 generation now
checks actual world-space bounds. If reduction loses extrema, unchanged LOD0
geometry may be used only while the aggregate LOD1 triangle budget permits it;
otherwise processing fails. The requested ratio is a target, not a guarantee of
reduction. Actual reported triangle counts describe the emitted geometry.
The outside-Blender proof independently checks each part's LOD0/LOD1 bounds.

The corrected positive fixture counter-rotates the socket locally to satisfy
its declared world-space rest-forward policy and asserts complete V0.7 geometry
validation. The Team Lead reran 143 processor/real Blender/frozen-golden tests
(all passed, 25.24 seconds), then after the final aggregate-budget check reran
80 processor/real Blender/V0.7 geometry tests (all passed, 27.64 seconds).
Logs: `.verification/blender-root-lod-revision.log` and
`.verification/blender-root-lod-final.log`. Targeted Ruff and mypy passed.
This correction is approved; the integrated workflow/cold export remains open.
