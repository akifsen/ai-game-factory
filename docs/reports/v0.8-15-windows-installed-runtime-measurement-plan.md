# V0.8-15 Windows installed shard 4 runtime measurement plan

Status: instrumentation corrected after the first unsuccessful full measurement;
optimization has not started. V0.8-14 source and exact installed-wheel technical acceptance closed
with three passes and no skips in each environment.

Natural main RC8 run 37128863703 reported two cancelled Windows installed shard
4 jobs (Python 3.11 and 3.12). Their annotations state that the 35-minute maximum
execution time was exceeded. This establishes a release blocker, not its cause.
No manual rerun or CI configuration change is authorized by this plan.

## Measurement contract

Use the canonical shard 4 identities, the exact installed wheel, an outside
checkout consumer, and both Windows Python versions. Preserve node membership,
test count, assertions, skips, real tools, and installed provenance. Record
setup/call/teardown durations, total wall clock, subprocess counts and time,
Godot/Blender/process-runner time, workspace/copy/hash costs, cold verifier counts,
and repeated immutable fixture construction. Report the ten most expensive nodes
and their share of total cost. Use another fresh local run only if needed to
establish repeatability; do not dispatch CI for discovery.

Do not optimize until both Python versions have timing evidence and the same
test identity or cost class recurs in independent fresh measurements. Repeat
the relevant version to confirm the hotspot; a single slow runner observation
is insufficient. No skip, deselect, cache semantics,
fixture lifetime or production behavior changes belong in the measurement step.

## Subsequent implementation contract

Delegate one measured cost class to the implementation engineer after review of
the measurements. Select the solution from evidence rather than assuming fixture
reuse, process startup or copying is the cause. Preserve isolation for mutable
state and race/currentness tests. Real Blender/Godot/cold verification remains
required wherever the existing tests require it.

Compare before/after hotspot time and whole-shard time with identical node and
PASS/SKIP identities and installed provenance. The proposed target is at most
28 minutes for each Windows version, leaving headroom under the unchanged
35-minute gate. Passing timing alone does not establish correctness or release
qualification. Do not add shards/jobs, redistribute tests, increase timeouts,
replace real tools with mocks, weaken assertions or change release gates.

This contract follows the existing ChatGPT coordination response dated
2026-10-03. It grants no release approval and claims no performance improvement.

## Prepared local instrumentation

`scripts/profile_v08_installed_shard_runtime.py` collects the canonical 106
shard-4 identities from frozen sources, records pytest setup/call/teardown,
checks outside-checkout installed origin/version before and after execution,
and optionally compares consumer package bytes with the supplied wheel. Fresh
report and workspace paths are required; the tool does not build/install wheels
or dispatch CI. No CI configuration or canonical inventory was changed.

The optional child observer records audit launch counts, transparent method
timings and named copy/hash/fixture entrypoint timings. Nested measurements may
overlap. Instrumented durations are lower bounds: positive audited launches do
not establish complete subprocess, Godot or Blender wall-time coverage. Those
total duration metrics remain explicitly missing; named entrypoint observations
are evidence for their recorded calls, not universal filesystem coverage.
Incomplete coverage must be resolved or bounded before optimization decisions.

Independent applied-checkout verification passed 58 tests in 15.86 seconds,
with scoped Ruff check/format and CLI help validation passing. Review caught
wheel provenance, Windows argument parsing, incomplete metric coverage and
recursive verification-test defects; their corrections are covered by the
remaining behavioral tests. The tool is approved for preparation only. Actual
106-test measurements, runtime overhead qualification and release evidence
remain pending.

## First measurement and correction

The first exact RC8 Windows 3.11 run selected all 106 canonical identities and
preserved installed provenance. It finished with 105 passes and one failure in
1709.90 seconds. The public session gate failed while preparing its foreign
workflow with WinError 267. This incomplete run is not a correctness-qualified
baseline, even though its timings are retained for diagnosis.

The observer also recorded one legitimate successful subprocess outside a node
phase. The validator initially rejected its missing node/phase attribution.
Such records now carry explicit `pytest_session` scope; partial node attribution
still fails validation. A real pytest session-finish regression covers this path.
Fresh basetemp children use exclusive `mkdtemp` creation with a short prefix;
same clock/PID calls cannot collide. Independent applied verification passed all
61 tests in 17.76 seconds, with scoped Ruff and whitespace checks passing.

A read-only empty-Python probe reproduced WinError 267 in the retained 260-character
foreign exporter staging directory with both Python 3.11 and 3.12. The shorter
188-character parent succeeded. This supports reducing path pressure for the
next measurement, but the exact failed exporter invocation was not replayed.
No production path handling or test assertions changed. Fresh complete runs on
both versions and repeated hotspot evidence remain required before optimization.
