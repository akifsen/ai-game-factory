# V0.8-15 Windows installed shard 4 runtime measurement plan

Status: planned; measurement and optimization have not started. V0.8-14 source
and exact installed-wheel technical acceptance must close first.

Natural main RC8 run 37128863703 reported two cancelled Windows installed shard
4 jobs (Python 3.11 and 3.12). Their annotations state that the 35-minute maximum
execution time was exceeded. This establishes a release blocker, not its cause.
No manual rerun or CI configuration change is authorized by this plan.

## Measurement contract

Use the canonical shard 4 identities, the exact installed wheel, an outside
checkout consumer, and both Windows Python versions. Preserve node membership,
test count, assertions, skips, real tools, and installed provenance. Record
setup/call/teardown durations, total wall clock, subprocess counts and time,
Godot/Blender/process-runner time, workspace/copy/hash costs, cold verifier counts,
and repeated immutable fixture construction. Report the ten most expensive nodes
and their share of total cost. Use another fresh local run only if needed to
establish repeatability; do not dispatch CI for discovery.

Do not optimize until both Python versions have timing evidence and a repeatable
hotspot is tied directly to profiling data. No skip, deselect, cache semantics,
fixture lifetime or production behavior changes belong in the measurement step.

## Subsequent implementation contract

Delegate one measured cost class to the implementation engineer after review of
the measurements. Select the solution from evidence rather than assuming fixture
reuse, process startup or copying is the cause. Preserve isolation for mutable
state and race/currentness tests. Real Blender/Godot/cold verification remains
required wherever the existing tests require it.

Compare before/after hotspot time and whole-shard time with identical node and
PASS/SKIP identities and installed provenance. The proposed target is at most
28 minutes for each Windows version, leaving headroom under the unchanged
35-minute gate. Passing timing alone does not establish correctness or release
qualification. Do not add shards/jobs, redistribute tests, increase timeouts,
replace real tools with mocks, weaken assertions or change release gates.

This contract follows the existing ChatGPT coordination response dated
2026-10-03. It grants no release approval and claims no performance improvement.
