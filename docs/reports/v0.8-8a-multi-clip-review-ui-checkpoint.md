# V0.8-8a multi-clip review UI checkpoint

This development slice adds an ordered clip selector to animation review. One
player builds two to eight bounded, individually bound authored clips on the
same character. It reuses the V0.8-6 clip validation and V0.8-7 review controls.
The existing canonical resources remain unchanged.

Selecting a known clip pauses playback, resets bone poses, deep-clones that
source animation and seeks to zero. The current speed and session loop setting
are preserved on the runtime clone. Invalid selector values leave state
unchanged. A new set scene retains the camera and controls and adds the selector.

Independent Lead verification with real Godot on Windows:

- Two sources loaded in caller order with distinct durations, source loops and
  disjoint Arm/Spine tracks. The original ten fixture files stayed unchanged.
- Actual selector and transport signals, all four playback speeds, seeking,
  restart, pause, session loop, same-clip restart and resize continuity passed.
- The full rendered inspector passed in 6.12 seconds, including both clips'
  weighted mesh deformation, unchanged source Animation tracks, root/capsule
  invariants and twelve bones. Camera framing passed at three viewport sizes;
  the rendered frame was visually inspected.
- Five invalid player configurations were rejected without installing a
  partial source library: one/nine clips, duplicate ID, bad SHA and unsafe path.
- Applied files matched the reviewed isolated implementation; applied controls
  and pose-reset verification passed in 6.37 seconds.

Lead and independent reviewer approved the three runtime/UI resources; Lead
also verified the new full inspector. This checkpoint does not claim completed
Python set export/currentness, two evidence-backed exported source packages,
final CI or an installed release-wheel result for the set feature. Those remain
the next integration slice. The current fixture is deliberately small and does
not represent final character art.

This work is on the separate multi-clip development branch. The v0.8.0-rc.3
release candidate source remains the completed V0.8-6/V0.8-7 change in PR #14.
Production and promotion eligibility remain false.
