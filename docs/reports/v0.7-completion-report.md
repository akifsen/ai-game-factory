### V0.7 acceptance contents

- `vehicle@1` authored **in real Blender** facing Blender's front view and exported with the default glTF exporter, i.e. a **+Z** source. Registered with `source_front=+Z`, normalized by exactly one 180° +Y root rotation, validated with groups `core, parts, orientation, pivot, sockets, collider_box`, imported and articulated in Godot (turret and barrel), rendered in seven views, cold-verified. Provider intents: 0.
- `weapon@1` from a `-Z` fixture (source retained byte-for-byte; prismatic slide articulated) and `aircraft@1` from a `+Z` fixture (propeller, rudder, elevator articulated; no sockets). Both cold-verified.
- A collapsed-pivot vehicle (the V0.7 spike defect) fails validation with `pivot.collapsed`, `pivot.position` and `socket.position` before Godot runs.

## Compatibility audit (step 18)

- `asset-profile-0.5.0`, `asset-spec-0.4.0`/`0.5.0`, `paid-request-0.6.0` and `asset-evidence-0.4.0`–`0.6.0` are unchanged; the V0.5 profiles keep their bytes, fingerprints and view vocabulary; `asset-spec-0.4.0.schema.json` is pinned by a canonical hash.
- The registry change is the documented transition: the historical AVAILABLE rows keep their values and order, `character`, `weapon` and `vehicle` leave UNSUPPORTED, and the V0.7 rows follow the historical ones. Both golden suites assert exactly that.
- The Godot harness keeps the 0.4.0/0.5.0 observation behavior for requests without `contract_v07`; the V0.6 paid-path acceptance and the V0.5 profile fixtures pass with it.
- The Blender script changes only for capsule profiles; box profiles export the same node set.

## Known limitations

1. Assemblies cannot be generated by a provider (by design, ADR 0016) and must carry their own LOD1 meshes when a LOD1 policy is chosen.
2. A `+Z` source registered as `-Z` is detected only where the profile declares a socket rest forward (vehicle, weapon); an aircraft has no such machine check and relies on the front review capture.
3. `derived_from` is recorded and validated as data only.
4. The committed Windows V0.4 bundles fail cold verification after a Linux checkout because their JSON line endings differ from the recorded hashes; the verifier on `main` gives the same result.
5. The `Windows` CI jobs and the remote Ubuntu jobs are the first run of this source on those hosts; see the pull request.
