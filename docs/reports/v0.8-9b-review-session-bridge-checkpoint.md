# V0.8-9b review session command bridge checkpoint

The one-shot command `python -m gamefactory.cli.animation_review_session_bridge` accepts absolute context, request, and fresh response file paths. It reconstructs existing candidate handlers from a guarded read-only `candidate-factory.db`; it does not reopen a managed workspace, migrate state, or write through SQLite. Requests use read/create/update, and update requires the expected exact raw session SHA and a domain operation.

The closed response contains six fields: schema_version, ok, committed, current, stored, and error. Successful mutations preserve the workflow's committed/current distinction. Historical read loads a valid sidecar before optional database authority checks, so missing database or failed currentness leaves notes readable with current=false. Create/update still require live authority. Missing or malformed transport requires a subsequent read; a missing response does not prove that a session write failed.

Input reads are bounded regular single-link files with identity/size checks. Context/exchange/request/response and the effective explicit/default session path are kept outside all immutable review, preview, animation, and original clip paths. Invalid context produces no response write. Responses use owned staged files and a stable per-destination exclusive publication claim. No-overwrite coordination covers cooperating bridge writers; uncooperative external filesystem mutation remains outside that guarantee.
