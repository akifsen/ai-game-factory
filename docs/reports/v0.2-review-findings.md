## Review method

The ProcessRunner author was Antigravity. A separate native reviewer reproduced
PR-01–03 and ran 29 focused tests. The Team Lead inspected the diff and returned
precise revisions. Those initial passing tests did not cover the reproduced gaps.

The Team Lead inspected contracts and requested CT-01/02. CT-03 was discovered by
the contract implementer during an actual engine launch. Final independent tests use the full CLI and packaged resources, not just direct harness execution.


## Additional integration findings

- CT-04 (major): a reused mutable Godot Dictionary aliased historical snapshots.
  The harness now copies three validated integer values per sample; the fixture
  deliberately reuses its dictionary to exercise this during real acceptance.
- CLI-01 (major): the first black-box CLI run failed during init at a spaced,
  Unicode Windows path because JSON output used the Windows console code page.
  Evidence: `.verification/v02/early-acceptance.json`. UTF-8 output correction is complete; successful repeated acceptance supersedes it.
  This failed run is not counted as successful evidence.
- COMP-01 (major): adding a null handler context to all approval scopes would
  invalidate unchanged V0.1 approval fingerprints. The exact prior scope is preserved when no handler context exists;
  the V0.1 compatibility test independently exercises this.
- SEC-01 (major): the new task-parameter update method must enforce the same
  credential rejection as initial persistence; bypassing it is unacceptable.

Two ProcessRunner test failures under host contention were rerun in isolation
and both passed (1.26 seconds). The tests had assumed a subsecond Python startup
and a one-second cleanup, despite existing cleanup budgets up to eight seconds.
They were corrected to test partial-output preservation and bounded cleanup
without those unsupported timing assumptions. Final full-suite evidence remains
required after all implementation changes.


- GD-01 (major, runtime-confirmed): `disable_project_settings_override=true`
  also suppressed `--script`; the normal game ran until timeout without observations.
  The Team Lead ran two identical 6-second-bounded experiments: true timed out
  (6.801 s), false completed (0.980 s) with an observation. Evidence:
  `.verification/v02/debug-harness-overrides/result.json`. Staging now excludes
  root override.cfg, clears the custom override pointer, removes controlled feature
  variants and keeps that flag false. Repeated full CLI acceptance passes with the correction.
- COMP-02 (major): task parameter refresh initially targeted the nonexistent
  `parameters` column; the actual V0.1 column is `parameters_json`. Corrected and
  covered by the independent compatibility test, including credential rejection.
- PATH-01 (major): a junction below the guarded scratch root could redirect the
  attempt directory. Nested managed components are now checked before creation;
  Windows junction tests exercise rejection before any outside write.
