# V0.8-12a animation compare runtime checkpoint

The new Python prepare/run API creates a disposable two-viewport Godot comparison
from a current public V0.8-8 review set. Each pane owns its character, animation
player and camera. One normalized timeline samples both clips at the same phase,
using the longer clip duration as the shared reference. Playback stops at the
endpoint; selection changes reset both panes while retaining the chosen speed.

Preparation checks public currentness before and after copying, compares raw
source/copy snapshots and cleans only its owned overlay on failure. Launch
rechecks currentness. Sources and session annotations are not written. The
runtime rejects duplicate selections and invalid speed/progress, resets sparse
bone poses on selection and bounds context reads before allocating input bytes.

Independent validation passed all 15 new tests with no skips, including a small
real Godot sparse-track runtime probe, malformed/oversized context rejection and
parse checks for all five new Godot scripts. Ruff check and format check passed.
After applying the isolated patch, the same 15 tests passed again in 5.35 seconds.
A separate reviewer approved this bounded runtime and fast-test checkpoint.

The probe uses an in-memory rig; it does not establish actual authored-package
rendering or weighted deformation. Full rendered two-viewport acceptance with
the existing three-clip Blender/Godot fixture, source-authority integration and
an independently installed wheel remain pending. V0.8-12 is not technically
closed or release-qualified. No CI infrastructure or frozen test inventory was
changed. See the [API guide](../guides/v0.8-12-animation-compare.md).
