# AI GAME FACTORY — V0.5 COMPLETION REPORT

## Engineering Decision

An asset profile is the processing contract for a class of asset. An asset specification is the value set for one asset. Built-in profiles are explicit registry entries (`static_prop@1`, `pickup@1`, `modular_piece@1`) loaded from strict YAML. They are not plugins, and profile documents do not execute caller code. Schema `asset-profile-0.5.0` is separate from `asset-spec-0.4.0` and `asset-spec-0.5.0`. A revision stores the profile version it was allocated with. Changing profile requires a new revision. Approval fingerprints include the profile id and version. Paid-cost policy stays on the approval and provider intent, not on the profile. See ADR 0008.

## Profile Architecture

`ProfileRegistry` loads three package YAML documents and lists nine other ids as UNSUPPORTED. `builtin_registry()` returns a new immutable registry; there is no mutable global profile state. Behavior is on `AssetProfile` methods (`processing_contract`, `scene_contract`, `runtime_requirements`, `capture_request_profile`).

## Supported Profiles

- `static_prop@1` — prop, LOD0 and LOD1, box collider, bottom-center or center origin, `StaticBody3D`, ray hit, views front / three_quarter / side, framing target 0.65 (range 0.55–0.75)
- `pickup@1` — pickup, LOD0 required, LOD1 optional, box collider, center or bottom-center origin, `Area3D`, no physics ray, views front / three_quarter / top, framing target 0.62 (range 0.50–0.75)
- `modular_piece@1` — modular, exact dimensions on a 0.25 m snap grid, tolerance 0.002 m, bottom-center origin, `StaticBody3D`, views front / side / three_quarter

Collider policies actually implemented: box. Convex and simple mesh are not advertised.

## Removed Hard-Coding

The 0.4.0 specification schema no longer is the only production schema. Review angles, framing fractions, Godot body, and LOD requirement come from the profile. The fake provider default asset id is `asset_under_test`. The one-meter scale reference is parked using the asset bounds plus the reference size, so a small pickup is not covered by the reference cube. Crate dimensions, budgets, and the golden files stay on the specification and the historical workspace.

## Blender Profile Processing

`process_asset.py` receives a processing contract JSON: dimensions, origin, LOD requirement, collider policy, tolerance. Output names use the asset id as a template. The pickup and modular fixtures completed real Blender processing inside `scripts/verify_profile_fixtures.py`.

## Validator Profiles

`validate_glb` uses the bound profile. Finding fields are unchanged. Modular assets also receive `dimensions.snap`. Mutation tests cover a missing static-prop collider, a missing pickup collider, off-grid modular dimensions, too many materials, an oversized texture, a truncated GLB, and a GLB whose node names belong to another profile.

## Godot Profile Integration

Staged scenes are generated from the profile scene contract. The pickup fixture wrapper contains `Area3D`. The modular fixture wrapper contains `StaticBody3D`. No gameplay script is generated.

## Runtime Profiles

The Godot harness reads body kind, ray requirement, review views, and framing fractions from the capture request. Pickup runtime does not require a physics ray. Common checks remain scene load, visible mesh, bounds, collision shape, and an empty error list.

## Render / Camera Profiles

Camera distance is computed from the asset bounding box, view, field of view, viewport, and the profile target screen fraction. Placed views in V0.5 are front, three_quarter (alias three_quarter_front), side, and top.

## Evidence / Receipt Compatibility

New bundles record profile id, profile version, review views, runtime requirements, and a production receipt. HTML links are limited to manifest paths. `scripts/verify_asset_bundle.py` matches the packaged copy. `read_production_receipt` adapts `asset-evidence-0.4.0` in memory.
