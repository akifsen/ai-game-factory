# V0.7 atomic publication review

One SQLite writer transaction binds verified attempt artifacts and revision pins
only while the publishing execution owns the latest running task. New rows must
be VERIFIED. Existing role references accept only VALID or VERIFIED rows owned
by the unique canonical stage in the same workflow. New pins and runtime-hash
suffixes require their current owner stage even when a matching row already
exists. Already-pinned values remain reusable by later stages.

Artifact IDs and casefolded paths are immutable, hash pins are write-once, and
runtime hashes are append-only. A mid-insert failure rolls back artifact and pin
writes together. Execution finalization independently rejects stale ownership.
Filesystem publication precedes this transaction and is not a SQLite atomic
operation; rejected stale workers can leave unregistered attempt files.

The Team Lead independently reproduced and rejected invalid-state and late-pin
bypasses during review. After correction, 135 publisher/frozen-golden tests passed
in 3.47 seconds (`.verification/publication-root-final.log`). The unchanged
finalization patch also passed 70 workflow/accounting/recovery/asset/redaction
regressions in 55.54 seconds (`.verification/publication-root-regressions.log`).
Final targeted Ruff, format and mypy checks passed. The implementation worker's
218-case run and independent reviewer APPROVED decision provide additional
support; they do not replace the Team Lead runs.

This persistence slice is approved. Integrated workflow, real DCC and cold
export acceptance remain separate gates.
