# Preliminary installed-wheel verification

This is a checkpoint, not release approval. The wheel was built while the
standalone V0.7 integration slices were under review; revised sources require a
new final wheel build and rerun before release.

The initial sandbox build could not reach PyPI. A permitted network build then
downloaded the declared setuptools build dependency and produced
`gamefactory-0.6.0-py3-none-any.whl` (SHA-256
`424d3bb12754a8f76383f10722a3e2bc0df5e342199be6d8c52e8626ef3faf83`).
Installation into a fresh, isolated virtual environment succeeded with the
declared runtime dependencies. No global Python installation was changed.

Under `python -I`, the source, geometry, Blender and Godot modules imported from
that environment's `site-packages`, and the packaged assembly Blender script,
Godot harness and cold verifier were present. Advanced profile availability
remained empty. The first smoke command mistakenly called the tuple-valued
availability property; the corrected command passed, with both logs retained.

An independent fixture then completed retained `+Z` source → real Blender
processing → source-preservation and geometry validation → real Godot runtime
and front capture using the installed wheel. The fixture injected a test-only
profile; it did not approve a production asset or create a paid operation.
Evidence: `.verification/wheel-root-real-runtime-r2.log` and
`.verification/wheel-assembly-inputs/installed-report.json`.

The installed stdlib-only verifier, run with `python -I` outside the project
source directory, also passed both retained legacy pickup and wall bundles
(20 files each). This confirms that those historical bundles remain usable
from this checkpoint wheel; it does not establish the future V0.7 bundle gate.
