# V0.7 profile catalog boundary

The legacy asset profile catalog remains the default. `builtin_registry()`
continues to expose the frozen V0.5 profiles and unsupported identifiers used
by existing workflows and golden behavior tests.

V0.7 uses `builtin_v07_registry()`, a separate explicit catalog. It currently
offers four candidate profiles: `vehicle@1`, `weapon@1`, and `aircraft@1` for
typed `local_operator_assembly` specifications through the local, human-reviewed
assembly workflow, and `character@1` as a reviewed candidate for provider-generated
single-mesh static characters (capsule collision, no rig). V0.7 parsing and the
assembly CLI use this catalog by default and do not fall back to a legacy profile
lookup.

Operators can inspect the catalogs separately:

```text
gamefactory asset profiles
gamefactory asset profiles --contract-version 0.7.0
```

The first command retains the existing V0.5 output. The second reports the
four V0.7 candidate profiles and unsupported identifiers. It does not accept
caller-supplied profile files or automatic profile discovery.

The candidate profiles have passed isolated local Blender and Godot workflows
on Windows 11 x86_64 with Blender 5.2.1 and the paired Godot 4.7.2 executable,
using named fixture approvals and cold evidence checks. A clean `0.7.0rc1` wheel
also passed all ten required installed-package groups outside the checkout under
`python -I`: 58 tests, zero errors and zero skips. Its 126 packaged files matched
the source and installed contents. Linux CI has not run for this candidate;
macOS acceptance has not been established. Candidate availability on Windows
does not establish a general product release.
